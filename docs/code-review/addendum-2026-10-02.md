## New findings

### F-40 · Unlisted valuation benchmarks are index averages chosen by sector label

**Severity:** Medium · **Category:** Integrity

**Where:** `backend/ceia/unlisted_research.py` (`_SECTOR_INDEX`, `sector_index`, `valuation_block`); `backend/app/services/analyzer.py` (`_unlisted_context`)

**What:** The relative models compare a company's P/B and P/E with the NSE index its UnlistedZone sector label maps to, or the Nifty 500 when none maps (about half of the 47 labels). The mapping is by regular expression on the label: exchanges and NBFCs map to Nifty Bank, "Construction & Infrastructure" to Nifty Realty, fintech to Nifty IT. The illiquidity discount (25%), equity risk premium (5.5%) and terminal growth (5%) are constants. A fast-growing company then reads "Rich": Garuda Aerospace (P/B 9.5, P/E 88) against Nifty 500 (3.1, 21.6) gives a fair value 70% below the quote.

**Impact:** The valuation pillar carries 35% of the call and can swing it by a full notch. A reader may take an index-average comparison for a peer valuation.

**Fix:** Build peer sets from named listed companies in the same line of business and use their median multiples with outliers trimmed; let the user change the discount; show the benchmark chosen at the top of the Call tab, not only in the Valuation tab. The site already labels the benchmark and lists the assumptions, so the output is honest about what it is; it is not yet a good peer comparison.

### F-41 · New unauthenticated endpoints fan out to upstreams

**Severity:** Medium · **Category:** Security

**Where:** `backend/app/routers/desk.py` (`/watchlist/snapshot`, `/market/movers-explained`, `/deals`, `/calendar`), `app/api/watchlist/snapshot/route.ts`, the analyzer re-run button

**What:** `POST /watchlist/snapshot` accepts up to 60 symbols and fetches each quote from Yahoo through a thread pool. `/market/movers-explained` makes one NSE request per mover. The Next route forwards the body to the data service without a check. Re-run starts a multi-minute analysis from one click. None of this needs a login.

**Impact:** Anyone who can reach the site can cause upstream traffic and CPU use well beyond what a page view costs, which can get the host's IP blocked by Yahoo or NSE. Extends F-05.

**Fix:** The same as F-05: authentication, per-IP rate limits, and a hard cap on distinct symbols per minute.

### F-42 · Movers explained makes sequential NSE requests inside the request

**Severity:** Medium · **Category:** Reliability

**Where:** `backend/app/routers/desk.py` (`movers_explained`, `_symbol_filings`)

**What:** On a cold cache each of the eight movers needs its own NSE announcements request, made one after another (the shared NSE session is not thread-safe, F-14, so they are deliberately not parallel). The result per symbol is cached for 10 minutes, but nothing coalesces two simultaneous cold requests (F-15), and there is no timeout budget for the endpoint as a whole.

**Impact:** The first request after a restart or after a mover list changes can take many seconds; the Market Watch page waits for it because it is fetched server-side.

**Fix:** Warm the filings for the current movers in the background after the movers refresh; return what is cached and say how many were still loading; add a total time budget.

### F-43 · Browser alerts: duplicates across tabs and silent skips

**Severity:** Low · **Category:** Correctness

**Where:** `components/alerts/alert-runner.tsx`, `lib/client/alert-rules.ts`

**What:** Every open tab runs its own checker, so two tabs can each fire, toast and notify for the same rule before the first write reaches the other. A check is skipped without a visible reason when the tab is hidden, or when the unlisted directory is still building (`unlistedReady: false`), so an unlisted rule can sit un-evaluated.

**Impact:** Duplicate notifications; an alert that has not been evaluated looks identical to one that has and not triggered.

**Fix:** Elect one tab as the checker with `BroadcastChannel` or a lock in `localStorage`; show "last checked" and a "waiting for unlisted prices" state on the rule.

### F-44 · Listed and unlisted companies are linked by name

**Severity:** Low · **Category:** Correctness

**Where:** `backend/app/services/unlisted.py` (`normalise_name`, `lifecycle_for`, `pre_ipo_match`)

**What:** The unlisted directory carries no NSE symbol or ISIN, so a listed company is matched to its earlier unlisted page on the legal name with "Limited", "Private" and similar words removed. Unlisted to listed now tries the ISIN first (added during this pass); listed to unlisted can only use the name.

**Impact:** A renamed company is missed, and two companies with the same name apart from the legal suffix would be linked wrongly. A false "Before it listed" panel would show another company's price history.

**Fix:** Read the ISIN from each company page once, keep it beside the directory entry, and match on it in both directions.

### F-45 · The same source page is parsed in two places

**Severity:** Low · **Category:** Maintainability

**Where:** `backend/app/services/unlisted.py` and `backend/ceia/unlisted.py` (`fetch_page_context`, `_fetch_directory`)

**What:** Both read UnlistedZone's HTML with separate regular expressions for the sector, ratios and price series.

**Impact:** A markup change on the site breaks two parsers that must be fixed together, and they can drift apart.

**Fix:** One parser in the engine package, imported by the service.

### F-46 · The research layer fails open

**Severity:** Low · **Category:** Reliability

**Where:** `backend/ceia/unlisted.py` (`analyse_unlisted`)

**What:** If the research layer raises, the error is logged and the run still completes with the timeline only. (During this pass the failure is now recorded in the JSON and the site shows it, rather than implying the run predates the feature.)

**Impact:** A systematic fault would produce reports that quietly lack the new sections.

**Fix:** Keep failing open, but count these in the run metadata so a rise is visible, and add the failure to the run's caveats.

### F-47 · The sitemap can block on a cold unlisted directory

**Severity:** Low · **Category:** Performance

**Where:** `app/sitemap.ts`

**What:** The sitemap includes every unlisted company and reads the directory server-side. With a cold backend that is a 30 to 55 second build.

**Impact:** A crawler's first request to `/sitemap.xml` can time out.

**Fix:** Use the cached directory only and fall back to the static routes when it is not ready.

### F-48 · The call can look decisive on thin data

**Severity:** Medium · **Category:** Integrity

**Where:** `backend/ceia/unlisted_research.py` (`compute_unlisted_verdict`)

**What:** Garuda Aerospace's page held 163 daily points, 22 revisions and 6 monthly returns. The call is capped at 65 conviction for that reason and the site shows a "short record" banner, but it still produces entry, targets, stop and share counts to the paisa.

**Impact:** False precision. The conviction cap does not change how the numbers are presented.

**Fix:** Round targets and levels to a sensible step for the price, drop the share-count table when the record is short, and show a range for the targets.

### F-49 · Test coverage is still very thin

**Severity:** Low · **Category:** Testing

**Where:** `backend/tests/test_unlisted_research.py`

**What:** The new tests pin the unlisted arithmetic: fact parsing, the sector map, the illiquidity discount, the sensitivity centre, VaR needing enough months, the bootstrap being reproducible, the valuation guard, whole-lot sizing and pillar weights. Nothing else in the repository has tests, including the new desk endpoints, the alert logic and every front-end component.

**Impact:** The risk list in the original [cross-cutting](cross-cutting.md#testing-recommendations) testing plan still stands.

**Fix:** Follow that plan; add the alert evaluation and CSV escaping as the first front-end unit tests.
